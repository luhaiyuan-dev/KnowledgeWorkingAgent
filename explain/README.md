# explain 阅读指南

本目录遵守“源码保持干净，解释放在独立 Markdown”的要求。命名规则是把源文件路径中的 `/` 或 `\` 换成点，并保留 `.py.md`，例如 `app/rag/loader.py` 对应 `app.rag.loader.py.md`。这样即使不同目录都有 `main.py`，解释文件也不会重名。

每篇说明采用同一套问题意识：这个文件解决什么问题、为什么放在这一层、每个类和函数怎样工作、输入输出是什么、为何不用另一种常见方案、会在哪里失败、如何测试、如何生产化、面试时怎样表达。源码故意采用展开式写法与清楚变量名，方便逐行对照。

建议先看配置与数据模型，再按 RAG 数据流阅读，之后看工具与 Agent，最后看入口和测试。
